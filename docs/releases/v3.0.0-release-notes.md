# UVHTTP v3.0.0 Release Notes

**Release Date**: 2026-10-18 (tagged) / 2026-10-20 (published as latest)
**Version**: 3.0.0
**Type**: Major Release (breaking API atomization)

## Overview

v3.0.0 is the window that was drafted as "v2.10". It ships as a major version because nothing in it is backward compatible: four deletions, two renames, and the atomicity defects those changes exposed. The rule in `docs/release-strategy.md` classifies an incompatible API change as MAJOR, so the earlier "keep the number at 2.10" exception was dropped rather than renewed.

The theme is **API atomization**: every public symbol either does what its name says or is gone. That meant deleting a built-in rate limiter that keyed one counter per server, a builder layer that carried framework behavior, fourteen config fields no execution path read, and request accessors that never named the object they acted on. The release also fixes the data-integrity bugs found while doing it.

## 💥 Breaking Changes

### Removed

- **14 `uvhttp_config_t` fields** (#472) — `read_buffer_size`, `max_body_size`, `max_header_size`, `max_url_size`, `max_requests_per_connection`, `request_timeout`, `keepalive_timeout`, the eight `rate_limit_*` knobs, `cache_default_max_entries`, `cache_default_ttl` and `lru_cache_batch_eviction_size`. `uvhttp_config_set_defaults` assigned them, `uvhttp_config_validate` range-checked them, and no execution path read them. The limits are now owned by compile-time constants (`UVHTTP_MAX_BODY_SIZE`, `UVHTTP_READ_BUFFER_SIZE`, `MAX_URL_LEN`, `UVHTTP_CACHE_DEFAULT_*`), recorded in `docs/spec/config-api.md`.
- **The builder layer and one-click startup** (#479) — `uvhttp_server_builder_t`, `uvhttp_server_create`, `uvhttp_server_run`, `uvhttp_server_stop_simple`, `uvhttp_server_simple_free`, `uvhttp_serve`, the verb helpers (`uvhttp_get` / `post` / `put` / `delete` / `any`), and the builder-only setters. UVHTTP is an HTTP service library, not a framework: `uvhttp_serve` registered default routes, ran the caller's event loop, blocked until Ctrl+C and printed to stdout. The primitives (`uvhttp_server_new`, `new_with_loop`, `take_router`, `take_context`, `listen_routes`, `stop`, `free`) are untouched.
- **The unprefixed request accessors** (#470) — `uvhttp_get_body`, `uvhttp_get_header`, `uvhttp_get_param`. `uvhttp_get_param` silently meant the *query* string. Use `uvhttp_request_get_body()` / `uvhttp_request_get_header()` / `uvhttp_request_get_query_param()`.
- **`auto_cleanup`** (#475) — written by the construction path, read by nothing.
- **The built-in rate limiter** (#483) — the seven `uvhttp_server_*rate_limit*` APIs, the eight `rate_limit_*` fields in `uvhttp_server_t`, the whitelist struct, and the `UVHTTP_FEATURE_RATE_LIMIT` build flag. The implementation was broken in ways the API hid: one `rate_limit_request_count` on the server made the window per-server, so a single client over quota returned 429 to every other client; `get_rate_limit_status` and `reset_rate_limit_client` accepted a `client_ip` argument they never read; the whitelist keyed through `sockaddr_in` and excluded IPv6. Window length, counting dimension, storage and eviction are application policy, so the library stopped guessing them.
- **`uvhttp_version_info_t.feature_rate_limit`** (#483) — the fields after it shift. This is an **ABI break**; assignment by field name is unaffected, positional initialization is not.

### Renamed

- **`uvhttp_server_set_router` → `uvhttp_server_take_router`**, **`uvhttp_server_set_context` → `uvhttp_server_take_context`** (#470). "Set" implied a borrow while the behavior was a transfer — the mismatch that made the official embedding example double-free on its listen-failure path. `uvhttp_server_free()` is the single release point.
- **Request declarations moved from `uvhttp_server.h` to `uvhttp_request.h`** (#476). Code that reached request APIs transitively now has to include `request.h`.

### Added

- **`uvhttp_server_listen_routes(loop, routes, route_count, host, port, &server)`** (#470) and `uvhttp_route_t` — route registration plus bind in one call, the supported replacement for `uvhttp_serve`. On failure nothing is allocated and `*server` stays `NULL`.
- **`uvhttp_server_set_request_filter(server, filter, user_data)`** (#483) — a single-slot pre-dispatch seam installed where the deleted limiter used to run, before protocol-upgrade detection and before the router lookup. Returning `UVHTTP_OK` continues dispatch; any other code stops it. If the filter returns an error without sending, the library sends 403 `Forbidden` as `text/plain` so the client is never left waiting. Passing `NULL` clears the seam.
- **[Request Filter API guide](../guide/REQUEST_FILTER_API.md)** with a per-client fixed-window snippet in user code, and the runnable `examples/03_middleware/rate_limit_demo.c`.

## 🔧 Migration

| v2.9.2 | v3.0.0 |
|--------|--------|
| `uvhttp_serve(loop, host, port)` | `uvhttp_server_listen_routes(loop, routes, n, host, port, &server)` |
| `uvhttp_server_set_router(server, router)` | `uvhttp_server_take_router(server, router)` |
| `uvhttp_server_set_context(server, ctx)` | `uvhttp_server_take_context(server, ctx)` |
| `uvhttp_get_body(req)` / `get_header` / `get_param` | `uvhttp_request_get_body(req)` / `get_header` / `get_query_param` |
| `uvhttp_server_enable_rate_limit(...)` and friends | Install a request filter; keep policy in your code |
| `config->max_body_size = N` and the other 13 fields | Set the owning compile-time constant (`UVHTTP_MAX_BODY_SIZE`, ...) |
| `#include "uvhttp_server.h"` for request APIs | Also `#include "uvhttp_request.h"` |

`UVHTTP_ERROR_RATE_LIMIT_EXCEEDED` (-550) stays: it changes from a code the library returned internally to an idiomatic code for the application's filter to return. Passing `-DBUILD_WITH_RATE_LIMIT=OFF` now produces a CMake unused-variable warning and nothing else.

## 🐛 Fixed

- **A failed router migration destroyed the routes it was converting** (#471) — `uvhttp_router_migrate_to_trie()` freed the registered route list on its failure path. Data loss since v2.7.2.
- **`uvhttp_response_set_body()` replaces atomically** (#473) — it freed the old body before allocating the new one, so an allocation failure left a stale length over freed memory.
- **LRU cache setters validate at the write point** (#473, #474) — setting `max_file_size` to 0 used to brick the cache: every later `put()` failed behind a stream of "File size exceeds limit" warnings.
- **A caller-set `Content-Length` is updated when the body is compressed** (#464) — a compressing response with a manual `Content-Length` advertised the pre-compression size while writing compressed bytes, mis-framing the stream. Trigger is narrow (compression is off by default), but the outcome was data corruption.
- **`uvhttp_static_prewarm_cache()` leaked every file it handled successfully** (#449) — the content is copied by `uvhttp_lru_cache_put()`, so the caller keeps ownership, but only the failure path freed it. ASan could not see this until the sanitizer jobs started compiling `uvhttp_static.c`.
- **`uvhttp_request_add_header()` rejects an empty header name** (#457) — RFC 7230 §3.2 requires at least one character; `add_header(request, "", value)` used to return `UVHTTP_OK`.
- **Construction failures report the actual cause** (#475) — a NULL host is `UVHTTP_ERROR_INVALID_PARAM`, a busy port is `UVHTTP_ERROR_SERVER_LISTEN`; both used to collapse into `SERVER_LISTEN`.
- **Cross-server handover is documented as unsupported** (#474) — one router or context belongs to one server. Enforcing it needs an ownership registry; that is a later breaking change.

## ✅ Testing & CI

- **119/119 tests** pass, with ASan in the pre-release gate and UBSan nightly. `BUILD_WITH_STATIC_FILES=ON` and `BUILD_WITH_ROUTER_CACHE=ON` are enabled there, closing the sanitizer blind spot that hid the prewarm leak.
- **A sweep of tests that could not fail** (#448, #453–#457): 4 zero-assertion tests, 51 silently-skipped `if` guards, 31 more inside four static-file tests, 7 always-green `if/else` pairs and 8 `server_new` precondition guards were rewritten as assertions. `scripts/ci/check_test_validity.py` now gates the always-green and silent-skip patterns.
- **New behavior tests** for connection close paths and `start_timeout` failure (#458), JSON error-response escaping (#460, `utils.c` to 100% line coverage), TLS certificate chain / load / subject extraction (#461–#463), and the `Content-Length`-plus-compression framing contract (#464). Each was mutation-verified.
- **CI stage split** (#465–#467): PR CI compiles and runs quality checks; tests moved to the pre-release gate; nightly keeps the long-running deep items.

## ⚡ Performance

No regression. The release gate pairs head against base **on the same runner in the same job**, because absolute RPS drifts by tens of percent between runs on shared runners:

| Endpoint | vs v2.9.2 | MAD | Pairs below 90% | Absolute median |
|----------|-----------|-----|-----------------|-----------------|
| `/` | **100.8%** | 2.8% | 0/10 | ~139K RPS |
| `/json` | **102.0%** | 0.8% | 0/10 | ~140K RPS |
| `/large` | **101.4%** | 1.0% | 0/10 | ~18K RPS |

The absolute figures are the v3.0.0 release-gate medians and are documentation only; see the [performance guide](../guide/performance.md) for methodology.

## 🔒 Compatibility

- **Major release: source and ABI incompatible.** Recompile against v3.0.0 and walk the migration table.
- The `uvhttp_version_info_t` layout changed (removed `feature_rate_limit`); `uvhttp_is_feature_enabled("rate_limit")` now reports the feature as unsupported.
- No deprecated compatibility shims were added. This is deliberate: the deleted APIs were either unread configuration or behavior that could not keep its contract.
