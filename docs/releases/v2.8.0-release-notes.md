# UVHTTP v2.8.0 Release Notes

**Release Date**: 2026-09-23
**Version**: 2.8.0
**Type**: Minor Release (Performance & Quality)

## Overview

UVHTTP v2.8.0 is a **performance and quality release**. The headline change is **zero-copy writev transmission for large responses — /large throughput +72.7% (5140 → 8881 RPS)**, eliminating a per-request 200KB memcpy plus two 100KB allocations. The release also lands a second-round code-review fix batch (17 defects), high-severity public API/build-system fixes that make `find_package`/`add_subdirectory` consumption work end-to-end, benchmark coverage for SSE/streaming/WebSocket, and PR-gate cleanups that replace placeholder jobs with real checks. 101/101 tests pass with ASan/UBSan zero findings; the /large regression baseline is raised to 8800 RPS.

## 🚀 Key Changes

### 1. 大 response 零拷贝 writev 发送 (PR #378)

**Problem**: 每个大 response 请求执行一次 200KB `memcpy` 并伴随两次 100KB 堆分配，是 /large 路径的主要瓶颈。

**Fix**:
- header + body 组装为 iovec，经 libuv `uv_write` 一次 writev 发送，消除整段拷贝
- TLS 路径与非法 client 场景自动回退原有拷贝路径，行为不变

**Result**: /large RPS **5140 → 8881（+72.7%）**；/large 回归门禁基线同步更新至 8800（PR #385）

### 2. 第二轮代码评审 17 项缺陷修复 (PR #380)

- **lru_cache**: OOM 路径 use-after-free 与淘汰逻辑死循环修复
- **config 双重归属多次释放**: server 持有 / context 借用归属厘清，消除 double-free（examples 同步修复 6 处）
- **错误码映射补齐**: `uvhttp_strerror` 覆盖全部 84 个枚举值，消除未映射回退
- **gzip 替换路径预算绕过**: 压缩缓存替换路径不再绕过内存预算检查
- **JSON 注入转义**: 输出 JSON 的用户数据正确转义
- **敏感词过滤**: 过滤逻辑缺陷修复
- **版本 fallback 漂移**: 版本号回退路径与 VERSION 文件一致

### 3. 公共 API / 构建系统高危修复 (PR #381)

- **install 不再发布第三方头与静态库**: `make install` 只安装 uvhttp 自有产物，第三方依赖（libuv/llhttp/mbedtls 等）头文件与静态库不再泄漏到消费者系统
- **特性宏 / 分配器类型 PUBLIC 传播**: `UVHTTP_ENABLE_*` 特性宏与分配器配置在构建接口中 PUBLIC 传播，消除消费者 ABI 错配（如启用压缩编译的库被未启用压缩的消费者链接）
- **find_package 全链路修复**: `uvhttp-config.cmake` / `uvhttp-config-version.cmake` / `uvhttp.pc` 重写，`find_package(uvhttp)` 与 pkg-config 消费者可用，嵌入验证项目全链路编译运行通过

### 4. 基准测试新增 SSE / 流式 / WebSocket 维度 (PR #379)

新增 `benchmark/ws_benchmark_client.py`，基准覆盖三种长连接/流式场景：
- `/sse` — SSE 推流，~60-68K streams/s
- `/stream` — chunked 流式响应，~9.5-10.8K req/s
- `/ws_connect`、`/ws_echo` — WebSocket 连接建立与回显

### 5. 嵌入与 CI 门禁改进 (PR #373 / #375 / #376 / #377 / #382 / #385)

- **发布门禁触发器回归修复** (发布 PR): PR #379 改动 `ci-benchmark.yml` 时基于改动前的文件，覆盖掉了 PR #373 已合并的 `release: [published]` 触发器，门禁退回 `push: branches: [pre-release]` 死配置（该分支从不创建）——不修复则 pre-release 不会触发回归门禁、两阶段发布流程静默跳过门禁。本次恢复触发器、job `if`、gate 步骤 `if` 与趋势落库条件（趋势仅在 `prerelease == true` 落库）
- **`BUILD_TESTS` 编译选项** (PR #377): 嵌入者可裁剪测试构建，不再编译 googletest
- **UBSan 门禁恢复 101/101 零发现** (PR #375): 修复预存测试中的非法枚举值
- **benchmark 回归门禁接入 release 事件** (PR #373): pre-release 门禁 + 趋势落库；原 pre-release 分支触发为死配置，发布流程改为两阶段 PR-only
- **PR 门禁占位 job 真实化** (PR #376): cppcheck 静态分析真实实现、format-check 仅检查变更文件、移除假 dependency-scan
- **CI 纳入 examples 编译验证** (PR #385): ubuntu-build job 编译全部示例，4 个坏示例重写、Makefile 依赖修复、e2e 14 目标补 `add_dependencies`
- **llhttp submodule dirty 显示** (PR #372): `.gitmodules` 增加 `ignore = dirty`（构建系统在子模块内就地打补丁）

## 🔒 Compatibility

- **零破坏性变更**: minor release，API 完全向后兼容
- **构建行为变化**: `make install` 不再安装第三方依赖头文件与静态库——直接依赖这些产物的消费者需自行集成第三方依赖
